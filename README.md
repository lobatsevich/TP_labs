## Лабораторная работа №4

### Выполненное задание (Вариант №6: Камни)
- **Определена иерархия драгоценных и полудрагоценных камней:** Создана объектная модель, разделяющая камни по их категориям с сохранением базовых характеристик (название, вес, цена, прозрачность).
- **Реализован отбор камней для ожерелья:** Камни успешно считываются из внешнего источника и формируют коллекцию элементов ожерелья.
- **Произведен подсчет общего веса и стоимости:** Сервисные методы безошибочно калькулируют суммарный вес ожерелья в каратах и его итоговую рыночную стоимость.
- **Выполнена сортировка камней ожерелья на основе ценности:** Элементы упорядочиваются по убыванию их стоимости за карат.
- **Реализован поиск по диапазону параметров прозрачности:** Написан алгоритм выборки, позволяющий находить в ожерелье камни, уровень прозрачности которых строго укладывается в заданные границы от `min` до `max` процентов.

### Выполненные требования к архитектуре и коду
- **Реализована полноценная иерархия наследования:** Базовый абстрактный класс `Stone` расширен производными классами с уникальными свойствами предметной области: `PreciousStone` (добавлено поле `clarityGrade` — класс чистоты) и `SemiPreciousStone` (добавлено поле `cutType` — тип огранки).
- **Выдержано разделение ответственности:** Классы-сущности пакета `entity` представляют собой чистые POJO-модели без методов бизнес-логики. Все функциональные действия (подсчет веса, стоимости, поиск и фильтрация) вынесены в отдельный сервисный класс `NecklaceAction`.
- **Применена сортировка через интерфейс Comparator:** Сортировка набора камней в ожерелье по их ценности реализована с помощью встроенного механизма `Comparator.comparingDouble`.
- **Реализованы порождающие паттерны проектирования:** Создание объектов автоматизировано и централизовано внутри класса `StoneFactory` с использованием паттерна **Factory Method**.
- **Соблюдена строгая пакетная структура:** Все классы приложения логически распределены по пакетам (`entity`, `factory`, `parser`, `action`) в соответствии с общепринятыми стандартами Java.
- **Оформление кода приведено к Java Code Convention:** Имена классов, методов, переменных, структура отступов и модификаторы доступа полностью соответствуют официальному руководству по стилю Java.
- **Реализовано чтение данных из текстового файла с валидацией:** Параметры инициализации объектов считываются парсером `StoneDataParser` из файла `stones.txt`. Среди входных строк присутствуют как корректные, так и заведомо поврежденные данные (отрицательные числа, текстовый мусор, некорректные диапазоны). Реализована отказоустойчивая обработка — поврежденные строки логируются и игнорируются, не прерывая выполнение программы.
- **Интегрирована современная система логирования:** В качестве фасада логирования подключена библиотека **SLF4J**.
- **Настроено разноуровневое и гибкое логирование:** В приложении задействованы логи разных уровней важности (`DEBUG`, `INFO`, `WARN`, `ERROR`, `FATAL`). Вывод логов в консоль разделен по цветам в зависимости от уровня, а также параллельно дублируется в файлы. Настроена ротация: текущие логи распределяются максимум по 3 файлам, а устаревшие автоматически архивируются в `.zip`.
- **Обеспечено полное покрытие юнит-тестами:** Весь написанный код полностью покрыт тестами с помощью фреймворка **JUnit 5**. Процент покрытия классов и строк составляет 100%.
- **Пользовательское меню для приложения не реализовано:** В соответствии с требованиями задание демонстрирует свою работоспособность исключительно через запуск автоматизированных тестов.
