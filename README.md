## Лабораторная работа №5

### Выполненное задание (Вариант №6: Каталог библиотеки)

- **Создан класс `Catalog` с внутренним классом `IssueRecord`:** Реализована модель каталога библиотеки, позволяющая хранить информацию об истории выдачи книг читателям. Внутренний класс содержит сведения о книге, читателе, дате выдачи и дате возврата.
- **Реализовано управление каталогом книг:** Добавлены методы регистрации книг, получения списка доступных записей каталога, выдачи книг читателям и оформления возврата.
- **Организовано хранение истории выдач:** История сохраняется после возврата книги, что позволяет отслеживать предыдущие выдачи и повторную выдачу одного экземпляра другому читателю.
- **Реализован контроль операций выдачи и возврата:** Предусмотрена обработка ошибочных ситуаций, включая попытку выдачи уже занятой книги, возврат невыданной книги и обращение к несуществующей записи.
- **Добавлен поиск истории выдач по читателю:** Реализована фильтрация записей с возможностью поиска по имени читателя без учёта регистра символов.
- **Реализовано получение активных выдач:** Добавлен метод, позволяющий получить список книг, которые в данный момент находятся у читателей.
- **Продемонстрировано использование анонимного класса:** Для фильтрации истории выдач создан анонимный класс, реализующий функциональный интерфейс `Predicate<IssueRecord>`.

### Выполненные требования к архитектуре и коду

- **Реализовано разделение ответственности:** Класс `Book` представляет сущность книги, `Catalog` содержит бизнес-логику управления каталогом и историей выдач, а `CatalogFactory` отвечает за создание объектов каталога.
- **Применён внутренний класс:** Класс `IssueRecord` объявлен внутри `Catalog` и используется для хранения информации об отдельных операциях выдачи книг читателям.
- **Применён анонимный класс:** Реализована анонимная реализация интерфейса `Predicate`, используемая при поиске истории выдач по имени читателя.
- **Соблюдена пакетная структура Maven-проекта:** Классы приложения распределены по пакетам `entity`, `factory` и `service`. Конфигурация логирования размещена в `src/main/resources`, а модульные тесты — в `src/test/java` с соответствующей структурой пакетов.
- **Обеспечена проверка корректности входных данных:** Реализована валидация идентификаторов книг, названий, авторов и имён читателей. Предусмотрена обработка некорректных операций с помощью исключений.
- **Предусмотрена защита коллекций:** Методы получения списка книг и истории выдач возвращают неизменяемые представления копий коллекций, предотвращая изменение их содержимого через возвращённые списки.
- **Интегрирована система логирования Log4j 2:** Подключены библиотеки `log4j-api` и `log4j-core`. Настроен вывод сообщений в консоль с указанием времени, уровня важности и имени класса.
- **Реализовано разноуровневое логирование:** Для регистрации основных операций используются уровни `INFO`, `WARN` и `DEBUG`. Логируются добавление книг, выдача и возврат, а также отдельные ситуации, связанные с нарушением правил работы каталога.
- **Подготовлены модульные тесты JUnit Jupiter:** Созданы тесты для проверки сущности `Book`, фабрики `CatalogFactory` и основной логики `Catalog`. Проверяются корректность операций, обработка исключений, сохранение истории выдач и работа фильтрации.
- **Пользовательский интерфейс не реализован:** В соответствии с требованиями лабораторной работа приложения проверяется посредством автоматизированных модульных тестов.
- **Настроена автоматизация тестирования через Maven:** Для компиляции проекта и запуска тестов используется команда `mvn clean test`. В качестве средства запуска тестов настроен `maven-surefire-plugin`.
